# Contributing

Use a local checkout and private deployment settings outside it. Submit focused changes with the problem, resulting behavior and relevant test results. Keep application interfaces in Ant Design and preserve the documented status-page visual system.

Run the commands in README before submitting. Tests must use documentation IPs, dummy IDs and temporary databases. Never upload production profiles, subscription links, private runtime data, account identifiers or diagnostic logs containing client traffic.

Changes to credential provisioning, revocation, SSH/firewall migration or public status projection require failure-path tests. Explain the effect on existing clients and rollback. Do not represent mocked deployment tests as Linux or phone acceptance.
