# 分流与 DNS

日常客户端默认规则模式：国内服务和局域网直连；需要固定出口的业务域名及出口核验域名先匹配独立 VPS 组。不要把“所有公网流量走代理”当作客户端完整验收。

## 规则顺序

1. 业务固定出口域名和核验域名 → 独立 VPS 组；失效时不得回落 DIRECT。
2. 回环、私网、链路本地地址 → DIRECT。
3. 通讯及媒体 CDN 的明确国内直连规则 → DIRECT。
4. 已验证规则集，保留顺序及 DIRECT/REJECT 动作，只把代理策略映射到独立 VPS 组。
5. GEOIP CN → DIRECT；最后的 MATCH 根据用户选定规则集保留。未明确选择时默认 VPS 出口。

不采用进程级全量直连替代域名规则，否则内嵌浏览器中的固定出口业务可能绕过约束。引用规则集时检查 RULE-SET、GEOSITE 等资源依赖，依赖不全必须报错，不能静默忽略。导入规则集仍是独立配置，不引入其节点、订阅更新地址、代理链或认证信息。

`scripts/routing.py` 提供中立规则编译与 DNS 设置。`render.py` 可读取 inventory 的 `routing_rules_file`（JSON 规则数组），将命名代理策略映射到生成的固定出口组。运行数据及外部规则数组留在私有工作目录，技能只记录规则逻辑，不记录提供者身份或凭据。

## DNS

- 国内直连域名使用国内解析器；直连最终连接通过 direct-nameserver 重新解析，避免使用海外 CDN 地址。
- 节点域名解析独立设置，防止解析依赖代理、代理又依赖解析的循环。
- 保留 TLS 证书验证；不复制私有 DNS URL、认证参数或 skip-cert-verify。
- fake-ip 对通讯域名发生兼容问题时设置明确例外，保留 DNS 劫持和缓存一致性。
- 配置与内核运行时都要检查；只修改磁盘文件不会自动改变已加载内核。

## 验收

备份 → 内核语法校验 → 独立配置落盘 → 通过客户端重新加载 → 查看实际连接规则/链路。至少覆盖国内站点、通讯媒体域名、固定出口查询和固定出口业务；专用 CLI listener 若固定绑定代理组，其行为与日常规则端口不同，不能混用验收。

国内请求命中 DIRECT；固定出口查询仍返回目标 IPv4；业务优先规则不能被 GEOIP CN 或默认直连覆盖。只关闭受影响域名的旧连接以触发重新匹配，不清空所有用户连接。应用内图片需实机重试，公共页面可达不能冒充某张图片已恢复。

参考：[Mihomo DNS](https://wiki.metacubex.one/en/config/dns/)、[规则优先级](https://wiki.metacubex.one/en/config/rules/)。Shadowrocket 原生规则使用 PROXY/FINAL 语法，配置模式和节点选择均需检查；不声称生成即已完成手机实测。
